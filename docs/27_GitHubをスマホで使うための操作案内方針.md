# GitHub操作ガイド方針（スマートフォン利用者向け）

版：0.3／2026-11-06。ユーザーにはGitHubアカウントがあるが、操作経験は少ない。**GitHubアカウントと新しいリポジトリの作成は利用者が完了済み。権限付与とCodex連携は未実施。**

## 1. 説明方針
- GitHub操作が必要になったその都度、iPhone/iPad Safariもしくは利用可能な公式アプリの**実際の画面に合わせた**日本語の操作手順を案内する。
- 1回に依頼する操作を最小限に分け、各操作で「どこを開く」「何を押す」「何が表示されれば成功」「失敗時の戻し方」を説明する。
- 画面名・ボタン名は変更され得るため、実作業の直前に公式画面またはドキュメントで再確認する。
- 英語UIでしか表示されない用語は、初出で日本語の意味を併記する。
- PC・ターミナル・git CLIの操作を前提にしない。AIエージェントのGit操作を許可できるなら、利用者のクリック操作は最小限にする。
- パスワード、二要素認証コード、個人アクセストークンのチャットへの貼り付けを求めない。

## 2. 初回セットアップの残手順（アプリ開発はまだ開始しない）
1. 作成済みリポジトリの現状の公開状態を確認し、Privateなら本人にSettings→General→Danger Zone→Change repository visibility→Publicへの変更を段階的に案内する（変更は本人が実施）。
2. ユーザーは準備パックのZIPを1個だけSafariからリポジトリへアップロードする。
3. Codex CloudをProアカウントから開けることを確認し、公式接続画面で当該リポジトリだけを許可する。
4. Codex Cloudでクラウド環境を準備し、**資料の展開と整理だけ**を指示する。ZIPを `docs/` に展開し、`AGENTS.md`などの指示ファイルを適切な場所に保存する。
5. 展開後のフォルダ・コミットとZIP元本の整合性を確認する。ここまで本体アプリのコードは作らない。
6. ホスティングはGitHub Pagesを使用する。GitHub FreeのためリポジトリはPublicとし、簡易パスワードUIを利用する。

## 3. 用語説明
| 用語 | 日本語での意味 |
|---|---|
| リポジトリ（Repository） | プロジェクトのファイルと変更履歴を保存する場所 |
| private | 権限のある人だけがソースコードを見られる設定 |
| コミット（Commit） | ファイルの変更を履歴として保存する操作 |
| ブランチ（Branch） | 安定版に影響しない場所で変更を試すための分岐 |
| プルリクエスト（Pull Request） | 分岐した変更を比較し、確認後に統合する手続き |
| マージ（Merge） | 確認済みの変更を安定版へ取り込むこと |
| ロールバック | 問題のある変更前の安定した状態へ戻すこと |
| デプロイ（Deploy） | 作成したWebアプリをサーバーに配置して利用可能にすること |

## 4. ユーザー判断とAI作業の境界
- Gitコミット・資料ZIPの展開・`docs/`への格納は、ユーザーが承認した**環境準備専用タスク**として開発開始前でも実施可能。アプリ本体の実装とテストは開始承認後に行う。
- 利用者の確認なしにprivate→publicへ変更しない。βテスターをリポジトリへ招待する必要は通常ない（閲覧するのはサイト）。
- 初回のみでなく、β招待／公開切替／秘密情報の設定／削除・復元操作は毎回の説明と明示承認を要する。
- サービスの画面をAIが実際に操作できないときは、現状を偽らず利用者に必要なUI操作を案内する。
