# 品質ゲート・初回一括開発の受入条件・検証設計

版：0.2／2026-11-05　開発前の判定ルール。**実行結果はまだ存在しない**。

## 1. 判定区分
各REQ-IDに対して必ず `not_started`（未着手）、`placeholder`（見かけのみ）、`implemented_unverified`（実装はあるが未検証）、`automated_passed`（自動テスト証拠あり）、`device_passed`（対象実機で証拠あり）、`failed`（不合格）、`blocked`（技術・環境制約）、`out_of_scope_by_user`（ユーザー承認で除外）を付ける。実装状態と試験状態を別列にすることが望ましい。

## 2. 初回一括開発の内部ゲート
| Gate | 判断対象 | 必要な証拠 | 失敗時 |
|---|---|---|---|
| G0 環境 | 開発リポジトリ、ライブラリ固定、テスト環境、参照文書 | Git状態、依存lock、コマンド実行ログ | 外部公開・実装開始しない |
| G1 モデル | Template/Variant/Project/Profile/Asset、スキーマ、マイグレーション | 型検査、単体テスト、旧データ試験 | 修正・差分記録 |
| G2 表示 | 画像・文字・図形・分割・エフェクト・粒子 | レンダリング画像、描画グラフ診断、視覚試験 | 該当REQを未合格と明記 |
| G3 作業フロー | Template→Variant→Project→複数出力 | E2Eログ、実際の出力PNG/ZIP | 主要シナリオ不可と記録 |
| G4 安全 | 保存復元、素材漏えい防止、診断匿名化、不正ファイル拒否 | 故障注入試験とエクスポートの実ファイル検査 | S0/S1として停止 |
| G5 モバイル | iOS Safari / Android Chromeで操作・保存・出力 | 実機名、OS、ブラウザ版、動画/記録、テスト結果 | **実機未確認**と表示 |
| G6 照合 | 全REQと実装・試験・既知問題の追跡 | カバレッジCSV、確認項目書、BUILD_REPORT | 完成申告をしない |

## 3. 提出を受け取る段階（利用者による運用開始前）
- 全REQ-IDについて実装状態が付与され、実装ファイル／UI導線／テストID／既知制約への参照がある。
- 基本的なバナー制作（画像差替え、タイトル入力、Variant選択、3プロファイル出力、保存・再開）が**実際に動作**する。
- 初回から診断パネル・素材なし診断ZIP・自己診断が操作可能である。
- 自動構図補正の固定/許可、斜め分割、個別FX、文字装飾、パーティクル等の難所について、成功・失敗・未実装の状態が隠されていない。
- S0/S1が未解決なら「実用版完成」とは判定しない。初回統合提出そのものは、未達一覧付きで提出可能。
- PlaywrightのモバイルエミュレーションはiOS Safari実機の合格記録に代用しない。

## 4. 完成に近づいた段階の条件
- 全ユーザー明示要件の実装根拠と検証状態が記録される。設計提案要件も放置せず、必要でなければ合意を得て変更。
- 主要シナリオS1～S6を、代表iPhone/Android/PCの対象環境で必要な範囲まで検証。
- データ消失／外部漏えい／操作不能／出力不能のS0/S1不具合0件。
- すべての「成功」と報告した項目に証拠。未検証は「未検証」のまま集計。
- 作品素材の意図しない外部通信なし、診断ZIPに既定で作品データなし。
- テスト用モックや最終出力に混入したガイドなど、開発版固有の挙動がない。

## 5. テストの層
1. **型・静的解析**：tsc、lint、依存バージョン・ライセンス・脆弱性。
2. **純粋関数の単体試験**：座標・幾何・最適化・決定論・Patch解決・ファイル名・連番。
3. **モデルとレンダラーの統合試験**：フォント/画像読み込み、FX順、マスク、PNG/ZIP、保存・復旧。
4. **PCブラウザE2E**：主要UIを実際にクリックし、操作後にPNG／データの検証。
5. **画像回帰**：固定フォント・同一OS/GPU/ブラウザ環境でgoldenを比較。微小なフォントAA差には合理的な許容差を設定。
6. **モバイル実機**：タッチ、ファイル選択、シート、保存・共有、画面回転、バックグラウンド復帰、高負荷と中断。
7. **ユーザー目視レビュー**：すみだまり、紙質感、レイアウトの自然さ、自動構図候補の妥当性。数値評価だけで完了しない。

## 6. 新たに追加する具体テスト
| Test-ID | 条件 | 合格内容 |
|---|---|---|
| RV-TPL-01 | 同じNodeへVariant/Project/Profileで異なる色・位置 | 規則どおりの出所と結果、スナップショット原本は不変 |
| RV-TPL-02 | Templateを更新した後、以前のProjectを開く | 旧Projectの見た目は明示同期するまで変わらない |
| RV-DAT-01 | ZIPのID衝突・壊れたJSON・展開量過大 | 既存データが変わらずエラーを表示 |
| RV-DAT-02 | 同一Assetを2箇所に配置 | keep/avoidは再利用可能、構図アンカーは独立 |

| RV-CMP-02 | θ0=-20、±15、bounded | 全候補θは-35～-5度内 |
| RV-CMP-03 | keep/avoidが完全重複 | 衝突診断、条件を満たせない説明、ハード制約違反なし |
| RV-CMP-04 | 同一入力で最適化2回 | 候補順位と値が同じ |
| RV-CMP-05 | 三角形のスプリット表示領域 | BBoxではなく実多角形との面積で評価 |

| RV-FX-02 | 分割線を非表示にする | 境界の分割状態を保ち線だけ消える |

| RV-SEC-02 | XSSを含むSVGやZIPパストラバーサルを読み込む | 実行・外部送信なし、拒否または安全化 |
| RV-UI-01 | iOS Safariで指操作・回転・バックグラウンド復帰 | 誤操作/データ消失なし、結果を端末証拠で示す |

| RV-AUT-01 | 同Projectで正式出力→再出力 | 連番が2回進まない |
| RV-AUT-02 | 複数出力の途中失敗 | 連番確定ポリシーに従い整合する |

## 7. 不具合再現レポート
`BUG-ID/REQ-ID/TC-ID/端末とブラウザ/発生日/再現手順/期待と実際/診断イベントID/匿名診断ZIP/原因/修正コミット/回帰試験結果`を必須項目とする。

## 8. 画像・性能基準
- 「60fps」「VRAM上限」などは現時点では未実測。端末を代表機種に固定し、ベースライン性能を採取した後に合格閾値を決める。
- PNG透過、画像分割線、可変ぼかし、すみだまりはgolden画像を作り、仕様に沿った視覚判定を実施。
- フォント描画差は環境差を別管理し、テスト通過と見た目の同等性を混同しない。
