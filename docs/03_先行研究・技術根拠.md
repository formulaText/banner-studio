# 先行研究・関連技術調査（開発資料）
版：0.2／確認日：2026-11-05。学術研究の手法と、ライブラリが標準で実装している機能を混同しない。

設計レビュー補足：`22`にFANBOXカバー容量の公式情報、Storage・Local Font・PixiJSの再確認を記載。ユーザー文章をフォントURLの`text=`へ含めない既定値は`20`参照。Webページの閲覧日は研究の刊行年を意味しない。

## 評価基準
- **直接参考**：今回の要求に近い問題を扱う研究・API。
- **応用候補**：概念は近いが、画像回転・ユーザー指定領域・レイヤー制御などは独自実装が必要。
- **比較候補**：代替実装・高速化の技術。
リンクは一次資料（学会・大学・公式ドキュメント・公式リポジトリ）を優先。論文の性能数値を今回のアプリの性能として転記しない。

## A. 自動構図・画像トリミング

### R01｜Tu et al., *Image Cropping with Composition and Saliency Aware Aesthetic Score Map*, AAAI 2020
- 一次資料：https://ojs.aaai.org/index.php/AAAI/article/view/6889
- 研究内容：顕著性だけでなく、切り抜き後の領域内の相対位置を踏まえた構図評価。
- 本ツールへの適用：keep領域の目標相対位置に対する誤差項を設ける。
- 限界：ユーザー指定のavoid領域や回転角度の最適化を直接提供するものではない。

### R02｜Cheng et al., *Re-Compose the Image by Evaluating the Crop on More Than Just a Score*, WACV 2022
- 一次資料：https://openaccess.thecvf.com/content/WACV2022/html/Cheng_Re-Compose_the_Image_by_Evaluating_the_Crop_on_More_Than_WACV_2022_paper.html
- 研究内容：単一スコアだけでなく注目領域の位置の寄与を考慮して再構図を評価。
- 本ツールへの適用：自動補正の説明可能な内訳（keepの面積・位置、avoidの可視率、角度差など）。
- 限界：同論文のモデルをそのまま実装する予定ではない。

### R03｜Liang et al., *PhotoRecomposer: Interactive Photo Recomposition by Cropping*, IEEE TVCG, 2018
- 一次資料：https://pubmed.ncbi.nlm.nih.gov/29990001/
- 研究内容：写真間の構図距離と、好みに応じて評価を調整するインタラクティブな再構図。
- 本ツールへの適用：候補提示→ユーザー修正→再試行の操作ループ。
- 限界：回転付きのバナー画像配置にそのまま転用するものではない。

### R04｜Cloudinary, *Custom Focus Areas* / *Automatic Gravity*
- 公式：https://cloudinary.com/documentation/custom_focus_areas
- 公式：https://cloudinary.com/documentation/image_automatic_gravity
- 実例：座標や名前付き領域を画像に登録し、自動的な切り抜きに反映する。エディタ用の領域入力UIがある。
- 本ツールへの適用：元画像に紐づく複数の領域メタデータと編集UIのモデル。
- 限界：ユーザー独自の「avoidのはみ出し方向」や「角度許可時の構図再現」を同等に扱うものとは確認していない。CloudinaryのクラウドAPIを必須依存にしない。

### R05｜smartcrop.js（MIT）
- 公式：https://github.com/jwagner/smartcrop.js
- 実装：候補クロップを評価し、`boost`で注目領域の重み付けが可能。
- 本ツールへの適用：自動補正の比較基準・任意の候補初期値。
- 限界：標準での回転探索・keep/avoid同時最適化・相対配置の再現ではない。更新状況・依存関係を採用前に確認。

### R06｜Avidan & Shamir, *Seam Carving for Content-Aware Image Resizing*, SIGGRAPH 2007
- 資料：https://www.merl.com/publications/TR2007-087
- 研究内容：重要度の低いピクセル経路を削除・追加してリサイズ。
- 本ツールへの判断：人物イラストの形が変化し得るため、当初の「元画像を動かして切り抜く」要件には不採用。将来の特殊変形候補。

## B. レイアウトと制約

### R07｜Badros & Borning, *The Cassowary Linear Arithmetic Constraint Solving Algorithm* (1998/1999)
- 一次資料：https://constraints.cs.washington.edu/solvers/cassowary-tr.html
- 研究内容：UI配置における線形等式・不等式の制約解決。
- 本ツールへの適用：タイトルとラベルの間隔、左右余白、親幅に対する配置など。
- 限界：画像回転の最適化は非線形であり別モジュールにする。

### R08｜Shen et al., *LayoutRectifier: An Optimization-based Post-processing for Graphic Design Layout Generation* (2025)
- 一次資料：https://onlinelibrary.wiley.com/doi/10.1111/cgf.70273
- 研究内容：整列、重なり、はみ出しを元レイアウトからの変化を抑えながら補正。
- 本ツールへの適用：サービス別プロファイルへの変換後に、タイトル・ラベル等の衝突を検出・調整する仕組み。
- 限界：任意の回転画像やエフェクトレイヤーは本ツール側で扱う。

## C. 描画・非破壊エフェクト

### R09｜PixiJS v8（WebGL renderer、filter、mask）
- 公式：https://pixijs.com/8.x/guides/components/filters
- 公式：https://pixijs.download/dev/docs/rendering.html
- 実装用途：GPU合成、描画ツリー、ぼかし、色調整、ノイズ、マスク、レンダーターゲット。
- 限界：一般的な画像編集UI、自由な調整レイヤー作用範囲、可変ぼかしは完成品として付属しない。v8のWebGLを基準とし、公式の開発版ドキュメントと実際の固定依存バージョンの差を確認する。

### R10｜Konva.js / Fabric.js
- 公式：https://konvajs.org/ ／ https://fabricjs.com/
- 用途：オブジェクトの選択・変形・操作とCanvas系描画の比較。
- 判断：PixiJSと同時に全面採用しない。統合コストを比較し、必要な部分だけ使用。

### R11｜OpenCV.js
- 公式：https://docs.opencv.org/4.x/d5/d10/tutorial_js_root.html
- 用途：画素ベースの解析、輪郭、マスク、しきい値、モルフォロジー、色分析。
- 判断：容量・起動・メモリ面から初期必須依存にはせず、独自実装では難しい処理を実証してから採否決定。

## D. モバイルWeb・フォント・保存・テスト

### R12｜MDN Local Font Access API
- 公式：https://developer.mozilla.org/en-US/docs/Web/API/Local_Font_Access_API
- 事実：限定対応の実験的API。端末内フォントの全列挙をiOS/Androidの前提にしない。
- 対応：FontFace/ファイルインポートや利用可能な既知のフォント名でフォールバック。

### R13｜MDN CSS Font Loading API
- 公式：https://developer.mozilla.org/en-US/docs/Web/API/FontFaceSet/load
- 用途：画像化の前に必要なWeb／インポートフォントを確実に読み込み、失敗を捕捉。
- 限界：読み込み成功のみでは個々の文字グリフの収録を保証しない。

### R14｜MDN Storage quotas and eviction criteria
- 公式：https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria
- 事実：IndexedDBは自動的に永久保存を保証しない。Safariの条件やストレージ不足で削除され得る。
- 対応：永続化要求の成否を確認し、ZIP外部バックアップと復旧導線を提供。

### R15｜Dexie.js Export/Import
- 公式：https://dexie.org/docs/ExportImport/dexie-export-import
- 用途：IndexedDBに保存したBlob等も含めてエクスポート／インポートする機構の参考。
- 限界：アプリ固有の参照・整合性検査・バックアップ暗号化は別途実装。

### R16｜Playwright Visual Comparisons
- 公式：https://playwright.dev/docs/test-snapshots
- 用途：UI・画像書き出しの視覚回帰。スクリーンショットのベースラインと比較。
- 注意：OS、フォント、GPUの違いで画像差分が出る。CIの基準環境を固定し、実機目視テストも併用。

### R17｜Lucide Icons License
- 公式：https://lucide.dev/license
- 用途：標準SVGアイコンの収録候補。ISCライセンス表記が必要。

## 研究と実装の線引き
- 学術研究は「構図指標の参考」であり、学習済みモデルやコードを採用したという意味ではない。
- 画像の回転・領域のはみ出し方向・独自アンカー・プロフィール別の手動overrideを同時に解く部分は本プロジェクト独自の設計・検証を要する。
- `CanvasRenderingContext2D.filter`は全環境の前提としない（MDN：https://developer.mozilla.org/en-US/docs/Web/API/CanvasRenderingContext2D/filter）。主系はGPU描画とし、実機でフォールバックを検証。

## 追加調査を開発AIへ依頼すること
1. 使用バージョンのPixiJSのAPIを固定し、mask/filter/renderTexture/extractの動作をiOS/Androidで検証。
2. ソフトライト等のブレンドモードの一致性、色空間・アルファ合成の差を実測。
3. Google Fontsとフォントファイルのライセンス、CORS、テキスト部分配信を確認。
4. サービス別画像サイズ・セーフエリアは公式・実測で再確認し、URLと日付を記録。
5. JSライブラリのライセンスと依存の更新頻度を導入時点で確認。
