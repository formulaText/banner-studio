# 実装仕様契約C：スプリット・レンダリング・非破壊エフェクト

版：0.2／2026-11-05。描画エンジンのAPI名を前提にせず、結果と操作の契約を固定する。

## 1. 描画グラフの責務
- 論理レイヤーツリー（永続化）と描画グラフ（毎回解決される計算結果）を分離する。
- 通常レイヤー／エフェクトレイヤー／グループ／画像コンテナ／マスク／分割線は、描画グラフ内で型と作用範囲を明示。
- プレビューと書き出しは同一の描画グラフ・効果順序を使う。解像度だけを用途に応じて変更できる。
- エフェクトON/OFFは元データを加工せず、描画グラフ内のノード有効性を切り替える。

## 2. スプリット線の意味
- SplitLineは**無限直線または親矩形内の線分**として幾何境界を定義。角度、基準点（位置）、反転、優先順を持つ。
- `decorative: false`のときもSplitLineは有効で、画像領域は分割されたまま。画面には境界の線を描かない。
- `SplitLineDecoration`は色・幅・パターン・不透明度・ブレンド・効果を持つ別ノード。装飾線を非表示にしても幾何境界は消えない。
- 1本の線は2つの半平面を作り、親の表示多角形との交差によって2領域を作る。複数の線は平面分割でセルを作り、各セルに画像スロットIDを関連付ける。
- 交差・隣接・極小セル・頂点の同位置判定に許容差を定義。断片化されたセルに対して同一画像を割り当てるかは明示したUI操作に従う。
- 2本目以降の線を挿入するとき、既存セルの領域IDを不必要に付け替えない。生成セルと画像の関連付けを履歴に残す。
- 分割境界の位置・回転は親コンテナの座標系で管理し、親の回転・拡大縮小を二重適用しない。

## 3. 画像のみをぼかす処理
```
slotA: sourceA → transformA → imageEffectsA → clipToCellA ┐
slotB: sourceB → transformB → imageEffectsB → clipToCellB ├→ mergeImages
                                                    ┘
mergeImages → (optional SplitLineDecoration) → composite
```
- 画像がぼかされても**分割セルの幾何境界は鮮明**なまま残る。
- ぼかし前にパディング済みテクスチャを確保するか、入力元の境界を延長して、クリップ境界付近の暗いハロー・滲みを防ぐ。
- 診断画面では `source → FX → clip → decoration` の各段階を可視化できる。

## 4. 分割線も含めてぼかす処理
```
mergeImages → SplitLineDecoration → isolatedRenderTarget → groupEffects → composite
```
- 線装飾を含む合成結果に効果を適用する。線のぼかし量もグループFXの設定に従う。
- 画像専用の個別FXを事前に適用してからグループFXを重ねてもよいが、独立したFXとしてON/OFF・Undoが可能であること。

## 5. 調整レイヤーの作用範囲
- **初期既定**：効果レイヤーの位置より下にある、同一の最近傍独立合成グループ内の兄弟レイヤーを対象とする。レイヤーより上の兄弟は対象外。
- グループが`isolated`の場合、外側の祖先や他グループの画像は変更しない。親グループへ意図的に対象を広げるには明示スコープ設定が必要。
- 特定オブジェクトを対象にする場合は、IDで指定した対象がスコープ内で解決できることを検証。参照切れは警告して無効化、他レイヤーを代わりに処理しない。
- 効果レイヤーは元のレイヤーを非破壊で残し、合成済みの下層を読み取り、適用後の結果として合成する。単純な半透明の「色を乗せる」表現とは区別。
- `visible=false`にした調整レイヤーは視覚効果を完全に除去できる。非表示でも保存設定は維持。

## 6. スタック順序と色合成
- 効果スタックは**定義された配列順**に実行。たとえば `blur → threshold → sharpen` と `sharpen → blur → threshold` は等価ではない。
- 透明度、マスク、ブレンドの順序をRenderGraphの各ノード属性として確定する。
- GPUでPremultiplied Alphaの境界処理、色空間（sRGB）、透明PNG、半透明境界、書き出しの縁ハローを検証する。
- ブレンドモードの実装可否はPixiJSの現行バージョンで実測し、対応不能なモードはエラー/制約表示する。黙ってnormalへ置換しない。
- RenderTargetの開放、再利用とGPUコンテキスト復旧をRendererAdapterの責務とする。

## 7. 可変強度ぼかし
- 領域マスク内の位置に応じてぼかし量を変える。中心から周縁へ強→弱、逆転も可能。
- 最初は有限段階のBlur結果を複数生成してマスク濃淡に従い補間する方式を検討。1枚のぼかし結果の透明度を変えるだけで「任意のぼかし半径」を完全再現したと称さない。
- 強度、フェザー、減衰曲線、対象領域の角丸、反転の値は保存対象。
- 画質・VRAM負荷が高い場合は「編集中の簡易プレビュー」と「最終出力の高品質処理」を区別し、出力側も処理ができない場合は失敗理由を返す。

## 8. ノイズ・パーティクル・グラデーション
- ノイズとパーティクルはseed、時刻、設定を固定して再現できるようにする（プロファイル間で寸法変化する場合は位置の相対化ルールが必要）。
- グラデーションは複数ストップ、反転、線形／放射状、形状マスク、各色のアルファを保持。
- 粒子は実時間プレビュー時のフレーム位置と、画像として書き出す採用フレーム位置を分離し、書き出しに乱数による予期しない違いが出ないようにする。
- 紙・プラ・マスキングテープ等のプリセットはスタイル定義と必要なテクスチャ参照からなる。素材の出所/ライセンスも管理。

## 9. 表示・書き出しの不変条件
- セーフエリア、選択枠、編集ハンドル、デバッグガイドは**本番書き出しへ入れない**。
- レイヤー表示OFF・マスクOFF・装飾線OFFは、それぞれ異なる意味として処理。
- 出力前に必要な素材・フォントの読み込み完了を待ち、不足による置換や品質低下は通知。
- 出力サイズ・形式・背景透明・色変換・FX精度は出力Manifestへ記録。
- 部分書き出し失敗時に成功済みの出力先を明示し、必要なら失敗分だけ再生成する。

## 10. 実証ケース
1. 斜め境界60°：各画像に独立ぼかし→境界線なしでも分割状態維持。
2. 画像ぼかし＋白の装飾線あり：線の輪郭は鮮明。
3. グループFXを追加：同じ白線もぼかされる。
4. 子グループの調整レイヤーをON/OFFしても隣の独立グループへ漏れない。
5. 2本の交差線、3枚以上、極小セル、分割線1本の角度90°/0°。
6. 透明PNGのエッジでハロー、色相、alpha差を定量/視覚比較。
7. 同じseed/frameでパーティクル出力を繰り返し、同じ入力で結果を比較。
