# 技術設計・データモデル（案）
版：0.2／2026-11-05　状態：実装前の推奨案。確認できない挙動を「対応済み」とみなさない。

※曖昧な挙動の規範的な判断は`16`～`20`の仕様契約を優先する。本ファイル内の型サンプルは導入例であり、確定スキーマではない。

## 1. アーキテクチャ上の結論
- **ドキュメントモデルを描画エンジンから分離する。** PixiJS等の表示オブジェクトは保存データの正本にしない。
- **TypeScript + Vite + コンポーネントUI**を基本とする。UIフレームワークはReactを暫定候補。編集キャンバスは**PixiJS v8 + WebGL2**を第一候補とし、実機で不可なら別実装を比較する。WebGPUは必須にしない。
- **OpenCV.jsは必須にしない。** 構図補正は領域幾何と制約付き探索によってブラウザ内で完結させ、必要が判明した際に画像解析を追加する。
- 非破壊効果はノードの論理ツリーと**中間レンダーターゲット／効果スタック**で合成する。下層全体へのぼかしと単一画像へのぼかしは別処理。
- データはIndexedDB（Dexie.js等で抽象化）と外部ZIPバックアップ。自動保存・履歴・スキーママイグレーション・素材ID参照を最初から持つ。
- テストはVitest（幾何・変数・保存）、Playwright（PCのUI、画像比較）、iOS/Android実機手動テストの併用。

## 2. 層の責務
```
UI ─── Commands/UndoRedo ─── Document Store ─── IndexedDB/ZIP
  │                                  │
  │                                  ├── Template Resolver
  │                                  ├── Responsive Layout Resolver
  │                                  ├── Composition Optimizer
  │                                  ├── Asset/Font Loader
  │                                  └── Export Coordinator
  │                                         │
  └──────── Canvas Interaction ───────── Renderer Adapter
                                            │
                                    PixiJS(WebGL2) + FX pipeline
```

- `Document Store`：テンプレート・バリエーション・プロジェクトの変更をコマンド形式で管理。アセットBlobは別保存。
- `Template Resolver`：Template snapshot→Variant diff→Project content＆diff→Profile responsive→Profile overridesの順で解決。入力へ破壊的書込みをしない。
- `Responsive Layout Resolver`：px、比率、アンカー、親基準、制約、レイヤー固有の表示設定を解決。循環参照検知を持つ。
- `Composition Optimizer`：`x,y,scale,rotation`の補正案を生成。レンダラーに依存しない純粋な関数。
- `Renderer Adapter`：解決済み表示ツリーをGPUで描画し、編集表示と書き出しで同じ表現を使う。
- `Debug Overlay`：純粋な計算結果とGPU描画状態を読み取り表示する。診断OFFでは計測処理を最小化。

## 3. 主要データ構造（最初にZod/JSON Schemaで厳密化する）
### 3.1 基本識別とマイグレーション
すべての永続データに `id`, `schemaVersion`, `createdAt`, `updatedAt` を持たせる。参照は安定したID（UUID等）。キーはプログラムの表示名で代用しない。読めない版のデータを黙って上書きしない。読み込み時の検証エラーは診断ログに残し、元ファイルを保持する。

### 3.2 型のイメージ
```ts
interface BaseRecord { id: string; schemaVersion: number; createdAt: string; updatedAt: string }
type Absolute = { unit: 'px'; value: number };
type Relative = { unit: 'ratio'; value: number; base: 'canvasWidth'|'canvasHeight'|'parentWidth'|'parentHeight'|'safeWidth'|'safeHeight' };
type Measure = Absolute | Relative | { unit: 'auto' };
interface FrameRule { x: Measure; y: Measure; width: Measure; height: Measure; anchor: 'tl'|'tc'|'tr'|'cl'|'cc'|'cr'|'bl'|'bc'|'br'; relativeTo?: string }
interface LayerNode { id: string; name: string; type: string; visible: boolean; locked: boolean; opacity: number; blendMode: string; frame: FrameRule; children?: LayerNode[]; payload: unknown; effects?: EffectNode[] }
interface Template extends BaseRecord { name: string; baselineCanvas: {width: number;height: number}; layers: LayerNode[]; variableDefinitions: Record<string, unknown>; sourceProfileId?: string }
interface Variant extends BaseRecord { templateId: string; name: string; patches: Patch[] }
interface Project extends BaseRecord { templateSnapshot: Template; variantSnapshot?: Variant; content: Record<string, unknown>; patches: Patch[]; profilePatches: Record<string, Patch[]>; assetIds: string[] }
interface OutputProfile extends BaseRecord { name: string; width: number; height: number; safeAreas: Polygon[]; overlayWarnings: Polygon[]; source?: {url?: string; checkedAt?: string; verified: boolean} }
interface ImageRegion { id: string; type: 'keep'|'avoid'; polygon: [number,number][]; priority: number }
// 構図アンカーと元配置はAssetではなく画像の配置インスタンスに保存する。詳細は`17`と`18`。
interface ImagePlacement { x: number; y: number; scale: number; rotationDeg: number; transformOrigin: [number,number] }
interface CompositionSettings { rotationMode: 'fixed'|'bounded'; maxAngleDeltaDeg: number; minScale: number; maxScale: number; weights: Record<string,number> }
interface EffectNode { id: string; type: string; enabled: boolean; parameters: Record<string,unknown>; scope: string; maskId?: string }
interface Asset extends BaseRecord { name: string; kind: 'image'|'font'|'svg'|'texture'; mime: string; sha256: string; license?: string; blobKey: string }
interface Patch { op: 'add'|'replace'|'remove'|'move'|'hide'|'show'; targetId: string; path?: string; value?: unknown; scope?: 'variant'|'project'|'profile'; baseRevision?: string }
interface Polygon { points: [number,number][] }
```
この定義は概念説明であり、実際のデータでは識別子への参照解決・Pathのバリデーション・安全な差分の適用規則を定義する。`remove` はソース要素削除ではなく作業データの削除／非表示差分になることがある。`Variant`差分と`Project`差分の衝突は「後の層が勝つ」規則を明示し、削除された要素へのパッチはエラーにする。

## 4. レスポンシブレイアウト
1. Template snapshot→Variant snapshot差分→Project共通差分を統合→2. Profile寸法を解決→3. Measure/アンカー・依存グラフを解決→4. レイアウトと自動構図補正→5. Profile固有Overrideを最後に適用→6. 最小/最大・安全領域・衝突診断→7. 描画グラフを作成。詳細は`17_仕様契約_継承と永続化.md`を正本とする。

他オブジェクト参照は循環参照（A→B→A）を診断する。汎用数値最適化／Cassowary（Kiwi等）は高度な制約が必要になってから追加する。初期は明示制約を手続き的に解決してもよいが、保存データモデルは制約を表現できるようにする。

## 5. 構図補正（設計上の核心）
### 5.1 座標系
- 元画像座標：0..1正規化した領域点。画像の向き（EXIF）適用後のピクセル基準に統一。
- 画像ローカル座標→スケール、回転、平行移動→出力キャンバス座標。
- 出力キャンバス：サイズごとにpxと0..1の相対位置を保持。参照点は右上等のアンカーを選択可能。
- スプリットでは「画像矩形」ではなく分割ポリゴンを**可視領域**として扱う。

### 5.2 目的関数の案
`E = w_keep*keepClipped + w_keepPos*keepAnchorError + w_keepSize*keepSizeError + w_avoid*avoidVisible + w_avoidDir*avoidExitDirectionError + w_scale*scaleDelta + w_rot*rotationDelta + w_blank*blankPenalty`。
厳密な値は正規化し、キャンバス幅・高さが異なっても比較可能にする。回転固定ならθは自由度に含めない。角度許可なら元角度±上限。`scale`は対数空間で探索すると倍率差に対して自然。条件が矛盾する場合は残差と採用理由を表示。

`keepClipped`：変換後keepと可視ポリゴンの交差面積に基づく欠落割合。`avoidVisible`：avoidの見えている割合。`keepAnchorError`：元のキャンバスでのアンカー基準の相対位置からの距離。`avoidExitDirectionError`：左下へはみ出す等の方向性を境界との関係で測定。`blankPenalty`：意図しない余白の面積。区域が競合する場合はpriorityを考慮する。

### 5.3 探索
- ①基準配置を新キャンバスへ比率変換、②回転の粗い候補生成、③位置/倍率の候補探索、④評価、⑤上位数候補を多段階で局所精密化。
- 同じ入力（画像メタデータ、元の構図、プロファイル、重み、探索設定）から同じ結果を返す決定論的計算にする。
- 1つの絶対解を保証せず、上位候補N件を保持し、診断パネルでスコア項目・不成立条件を見られる。
- 検証：人物風合成画像で「右上の顔＋左下の腰＋右倒し」、左右反転、縦横比極端、keep/avoid重複、回転範囲0、空白回避、分割領域等。
- 画像をAIが意味的に認識しているわけではない。keep/avoidは人が指定する。smartcrop.js等は自動候補の追加に使えるが必須依存ではない。

## 6. スプリット・マスク・エフェクト
- 分割線：中心点と法線（または角度）で半平面を表現し、親コンテナと交差させ各画像スロットをポリゴン化。複数線の交差時には生成セルとスロットの対応付けが必要。
- 順序A（線鮮明）：各画像→画像固有FX→分割ポリゴンでクリップ→合成→分割線装飾。
- 順序B（線にも効果）：各画像→クリップ→分割線装飾→グループを中間テクスチャへ→グループ全体FX。
- 下層全体の効果レイヤー：対象レイヤーを中間バッファへ合成→領域マスク/可変効果→元画像と合成。下層のすべてに逐次同じフィルターをかける方式は、合成後のフィルターとは結果が異なる点に注意。
- 可変ぼかし：単一のblur+alphaでは空間変化するblur半径を厳密再現しない。まず離散半径の複数ぼかし画像＋強度マスクの補間を検証し、品質不足ならカスタムシェーダーへ。
- ノイズは乱数シード固定、出力プロファイル間の再現性を定義。透明画素・Premultiplied Alpha・色空間を揃える。
- 紙・プラ・マスキングテープの装飾は非破壊の効果グラフと必要に応じたテクスチャ素材として扱い、使用ライセンス情報を残す。

## 7. テキスト／フォント
- `Intl.Segmenter`（grapheme）でユーザーが認識する文字のまとまりを得る。ただし実際の字形形成（グリフ合成、カーニング、縦書き等）とは区別し、文字列全体の幅を計測した結果と文字単位装飾の座標を整合させる。
- 文字列の内部状態は文章・段落・装飾規則・例外指定に分け、入力文字列が変わっても文字ごとの装飾が生成し直されるようにする。
- FontFace APIでインポートフォントを読み込み、`document.fonts.load`/`ready`の完了を確認してから画像出力。Webフォント取得失敗と字形欠落は警告し、黙って確定PNGを生成しない。
- Local Font Access APIは限定対応。iOS Safari/Android Chromeを主対象に**ユーザー選択ファイル経由のフォントインポートを含める**。OS内フォントの全列挙は必須にしない。
- すみだまり：文字マスク→ぼかし→階調・しきい値→エッジ補正→元字形と合成する効果グラフを試作。パラメータが文字内容に応じて再実行される。

## 8. テンプレート・変数・連番
- VariantはTemplate要素IDに対する差分として保存し、Project生成時にはTemplateとVariantのスナップショットを持つ。既存テンプレ編集が過去のProjectを暗黙に変更しない。
- 変数は`{{title}}`, `{{date:YYYY.MM.DD}}`, `{{serial:03}}`等を暫定例とする。実際の構文は統一し、文字列注入や循環参照を防ぐ。HTMLはエスケープ表示。
- 日付は端末ローカル・指定タイムゾーンの差を明示。連番はシリーズごとに採番を確定するトランザクションを用意し、プレビュー表示で勝手に加算しない。
- 出力前にファイル名をプレビューし、禁則文字・同名衝突を回避。

## 9. 保存・バックアップ
- IndexedDBにProject、Template、Variant、Profile、Assetメタ、Asset Blob、診断セッションを分ける。`sha256`で素材の重複を検出する（ハッシュ検証と参照整合性チェック）。
- 自動保存に失敗した場合にエディタが「保存済」と表示しない。`QuotaExceededError`を捕捉し、ブラウザ容量の推計を案内。
- ZIPバックアップの内容：`manifest.json`、保存レコード、Blob、`schemaVersion`、SHA-256一覧。書き戻しは検証→プレビュー→適用の順で、既存データを壊さない。
- 外部フォントファイルをZIPへ同梱する前に許諾を確認／ユーザー確認。バックアップには任意の「素材なし」モードを用意。
- 不可逆操作は確認を要求し、Undo履歴と永続保存の境界を明示。

## 10. タッチ操作と実機性能
- キャンバス座標と端末タッチ座標を分離。パン/ズームと要素移動/回転をジェスチャーモードで排他制御。
- 高解像度画像はプレビュー用ダウンサンプルを使い、原本Blobを保持。書き出し時は必要な解像度で再レンダリング。
- GPU中間テクスチャのプール/解放、フィルターキャッシュ、ブラウザのコンテキストロストからの復旧を用意。
- iOS Safari/Android Chromeで巨大画像・複数ぼかし・複雑なマスク・出力の実機負荷計測を実施し、無理ならプレビュー精度の段階調整とエラー表示を実装。見え方は公開時に同じ処理順を守る。

## 11. 安全・運用
- SVGはスクリプト・外部参照・イベント属性などを無効化／サニタイズ。テンプレートインポート時にJSON検証し、任意コードの実行を許可しない。
- CORS未許可のURL画像をCanvasへ混ぜない。読み込み失敗、書き出し汚染（taint）を明示。アップロードしたローカル素材を無断で外部送信しない。
- ログ・診断ZIPは画像・署名・ユーザーテキストを既定で含めず、明示的に同梱選択できる。
- 依存ライブラリのライセンスとセキュリティ脆弱性を検査し、固定バージョン＋ロックファイルをコミットする。最新番号を勝手に推測して記述しない。

## 12. API／モジュール間契約（実装の入口）
- `resolveDocument(template, variant, project, profile): ResolvedDocument`
- `layoutDocument(resolved, viewport): LayoutResult & Diagnostics`
- `optimizeComposition(source, regions, sourcePlacement, targetPolygon, settings): Candidate[]`
- `buildRenderGraph(layout): RenderGraph`
- `render(renderGraph, quality, time, seed): RenderOutput`
- `exportProfiles(projectId, profileIds, exportSettings): ExportManifest`
- `createDebugBundle(session, {includeAssets:false}): Blob`
- `validateImportedBundle(blob): ValidationReport`
Pure functionと副作用のある処理を分離し、各入出力の単体テストを作る。

## 13. 採用前に確認する分岐
- PixiJSでタッチ編集・フィルター・PNG出力の全要件が満たせなければ、Konva/Fabricまたは描画処理の限定的な置換を評価。ドキュメントモデルは維持。
- WebGL2未提供の端末では、画面だけ表示して完成とせず「必要機能が利用不可」を診断する。Canvas2Dへの完全フォールバックは別途工数評価。
- Reactの導入は、選択状態とキャンバス描画の疎結合が保てるかで判断。必要なら軽量UI管理へ変更。


# Ver.0.3補足：実機・配信・保存に関する構成上の境界

1. iOS Safariの実機確認を第一優先とする。iPadOSも実際の対象端末上で試験する。Android/PCは互換性要求として維持し、AIが利用できる自動試験と本人のiOS実機証拠を区別する。
2. 静的Webアプリのコード／配信（HTTPS、入口のクライアント側簡易パスワード画面を用意）と、利用者が作成した素材・テンプレート等のデータ保存（端末ブラウザ内）を分離する。
3. GitHubリポジトリとGitHub Pagesは双方Publicとする。クライアント側の簡易パスワード画面に機密保護を期待しない。
4. IndexedDBは端末・オリジン単位。iPhone↔iPad間のデータ共有には明示的なバックアップの書き出し／取り込みを用いる。端末間の自動同期は初期実装しない。
5. 将来のβ参加者のデータも原則として各端末の保存域に隔離する。ユーザーコンテンツをサーバーへアップロードする機能は、本要件に含まれない。
6. モジュール単位改修を容易にするため、公開された型／スキーマ／API境界を契約テストで守り、UIモックの確認と実機・レンダリングの品質ゲートを分ける。
7. 配信先はGitHub Pages（GitHub Free・公開リポジトリ）に確定。Vite製の静的アプリはGitHub Actionsでビルドして配信する。外部ホスティングや実効的な認証サービスは使用しない。
