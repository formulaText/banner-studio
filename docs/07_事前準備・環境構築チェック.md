# AI一括開発の事前準備・環境構築チェック
版：0.2／2026-11-05。□は作業前、☑は確認済みとして使う。ここでは未確認事項を「完了」扱いにしない。詳細なサービス用途の分離と確認状況は`22`を正本とする。

## 1. プロジェクト環境
- [ ] 空の開発リポジトリを用意し、Gitと初回コミットが利用可能。
- [ ] `docs/`以下に開発パックを全ファイル配置し、`AGENTS.md`等をルートへコピー。
- [ ] Node.jsとパッケージマネージャー（npm/pnpm等）のバージョンを固定。`package-lock.json`等を保存。
- [ ] TypeScript/Viteを導入し、`typecheck`、`lint`、`test`、`build`の実行手段を整備。
- [ ] 実際に利用するAIコーディング環境がファイル作成・シェル実行・ブラウザ操作・Gitコミットを許可されているか確認。名称だけで権限があると推測しない。
- [ ] リポジトリへのアクセスと成果物書き込み権限を確認。
- [ ] デバッグ用ログ・再現用アーカイブを保存する作業ディレクトリを設定。
- [ ] `.gitignore`に作品画像、個人素材、秘密情報、診断ZIP、ビルド生成物を適切に指定。

## 2. 実機・ブラウザ
- [ ] iOS端末の機種/OS版/Safari版がわかる。
- [ ] Android端末の試験環境があれば機種/OS版/Chrome版を記録し、なければ未実機検証と明記する。
- [ ] PCブラウザの試験環境があれば機種/OS版/ブラウザ版を記録し、なければ未実機検証と明記する。
- [ ] スマホから開発版へアクセスできるHTTPSホスティング方法を決める。ファイル直開きでのみ動く実装は採用しない。
- [ ] カメラロール/ファイル選択、ダウンロード、複数画像選択、画面回転、バックグラウンド復帰が試せる。
- [ ] WebGL2、読み込み可能な最大画像、ストレージ推定、フォント読込の自己診断ページを用意。
- [ ] オフライン時に何が使えるかを明示（外部フォント初回配信を含める場合は完全オフラインを保証しない）。

## 3. 画像・フォント・装飾の試験素材
- [ ] 著作権を保有するか、利用許諾を確認できる人物風イラストを2～3点。なければ幾何学図形で作った合成素材で代用。
- [ ] 顔keep・腰avoidを含む矩形/多角形の正規化メタデータをCSV/JSONで用意。
- [ ] 斜め分割に使用する不透明画像と透過PNGを各2点。
- [ ] 縦長・横長・正方形・高解像度・小画像・EXIF回転ありの画像。
- [ ] 日本語文字列（ひらがな、漢字、句読点、結合文字、絵文字、長文、改行）のテスト入力。
- [ ] Webフォント、許諾付きのインポート用フォント、読み込み失敗のケース。
- [ ] ロゴ・サインは検証用ダミー素材を使用。本物は初期診断ZIPへ入れない。
- [ ] 紙・プラ・マスキングテープの素材または生成パラメータ（第三者の無断転載を含めない）。

## 4. 出力プロファイルとセーフエリア
- [ ] pixivFANBOXの画像サイズ・表示場所・OGP/ラベル重なりを公式資料または実測で確認。
- [ ] Fantia、Ci-en、SNS等を対象にする場合は、対応する各サイズ・形式・実表示を確認。
- [ ] プロファイルごとに `sourceURL`, `checkedAt`, `confidence`, `notes` を保存。
- [ ] 検証前は「1200x630」「1080x1080」「1080x1350」等を**仮の検証プロファイル**として扱う。各サービスの公式仕様と断定しない。
- [ ] セーフエリアは画像に含まれない編集オーバーレイであることをテスト。

## 5. 外部ライブラリ／素材の利用条件
- [ ] PixiJS, Vite, React（採用時）, Dexie, Playwright, icon setのライセンスを収録。
- [ ] 同梱するSVGアイコンの許諾と帰属表示の有無を記録。
- [ ] フォントのWeb利用・画像作成・ZIPへの再配布許諾を区別して確認。
- [ ] テクスチャ素材の再配布許諾を確認。
- [ ] 外部URL画像・SVGを利用する場合、CORS・プライバシー・XSS対策を定義。

## 6. 事前に固定する運用ルール
- [ ] 書き込み失敗時の扱い、セッション復旧方法、ZIPバックアップの導線を初回実装範囲に含める。
- [ ] 日付・連番の確定時点を仮決定（例：正式出力確定時にのみ採番を進める）。
- [ ] デバッグZIPは作品画像・署名・入力全文を既定で含めない。
- [ ] 機能の状態分類を実装済／仮実装／未実装／実機未確認に分ける。
- [ ] 実装不能または遅延が生じても、仕様の削除ではなく`implementation-gaps.md`へ理由を記録。
- [ ] 出力の完全再現性はレンダラー・フォント・色空間・GPU差を考慮し、同一環境で検証する。

## 7. 開発AIへ渡す前に最低限決めるもの（初回は暫定値可）
- [ ] アプリの作業名（仮称可）とリポジトリ名。
- [ ] ローカル保存を基本とするか、クラウド同期を導入するか：**暫定はローカル優先・サーバー必須ではない**。
- [ ] 初期プロファイル：**検証用の仮サイズ3種**。
- [ ] シードや構図探索の既定値：実験用とし、UIから変更可能にする。
- [ ] バックアップの保存形式と読み込みルールを決める。

## 8. 開発AIが着手直後に生成するもの
- `ARCHITECTURE.md`：採用した実際の依存・バージョン・図、理由、代替候補。
- `DECISIONS.md`：技術決定の記録（ADR方式でもよい）。
- `TEST_ENVIRONMENTS.md`：各ブラウザ/端末をどこまでテストできるか。
- `GAPS.md`：現時点で未実装・確認不能な要件IDと理由。
- `BUILD_REPORT.md`：ビルドとE2Eを実際に試した証拠。

## 9. 開発後、ユーザーが最初に行う操作
1. 公式に確認したダウンロード方法で起動。
2. 「サンプルからバナー作成」→3つの出力先プレビュー→PNG出力を試す。
3. 診断モードをON→自己診断→素材なし診断ZIPを作って中身を確認。
4. 実際のメイン画像・文字へ差し替え→斜め分割→角度変更許可の自動補正を試す。
5. 保存→ブラウザ終了→再度開いて復元を確認。
6. 問題を発見したら確認項目ID・実機・操作手順・診断ZIPを記録し修正へ回す。
