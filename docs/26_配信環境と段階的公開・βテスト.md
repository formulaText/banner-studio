# GitHub Pagesを使った公開運用とβテスト

版：0.3.2／2026-11-06。状態：開発未開始／ZIP未アップロード／初回デプロイ未実施。ユーザーの明示決定を反映。

## 確定方針
GitHubのみでコード管理・AI開発の成果保存・サイト公開・動作確認を行う。GitHub Freeの**公開リポジトリ（Public）**から**GitHub Pages**で配信する。Cloudflare等の外部ホスティング、GitHub Codespacesへの切替え、実効的なログイン基盤は導入しない。現存リポジトリがPrivateの場合の公開設定変更は、ユーザー本人に操作手順を案内し、本人が行う。

### 運用段階
| 段階 | 公開状態 | 利用方法 | 承認 |
|---|---|---|---|
| S0 準備 | サイト未公開 | 文書ZIPアップロード、Codex接続、文書展開のみ | 本体開発・デプロイは実施しない |
| S1 本人中心の試験 | サイトはPublic | 軽いパスワード入力UIを設け、本人が試用 | 初回デプロイに承認が必要 |
| S2 知人β | サイトは引き続きPublic | 同じ入力UIを使い、知人にURLと共有用の簡易パスワードを案内 | β案内に承認が必要 |
| S3 一般向け告知 | サイトは引き続きPublic | 簡易ゲートは任意で解除可能 | 告知・ゲート変更に本人の承認が必要 |

## 簡易パスワード画面
- ブラウザ内のJavaScriptのみでチェックする軽量な入力画面を初期実装から用意する。
- 不一致時は通常UIを表示せず、再入力できる。正しい入力なら編集UIを使える。セッション単位の通過状態保持・明示ログアウト・共通パスワード変更・ゲート無効化設定を検討する。
- 公開HTML/JavaScriptを解析することで回避可能。**秘密情報の保護機能として説明しない**。ハッシュ化してもクライアント側のみでは真正の認証にならない。
- 実際のGitHubアカウントパスワード等を流用しない。パスワード文字列を公開リポジトリの設定値や文書に平文で書かず、軽い障壁を実装する場合でもデモ用文字列を区別する。
- 本人の制作画像・署名・未公開情報を静的配信アセットやGit履歴へ入れない。実制作素材はユーザー端末内に保存する。

## GitHub Pagesの構成
- 既存の公開リポジトリ1件で管理する。TypeScript/Viteアプリのビルド済み`dist/`だけをGitHub ActionsでPagesへデプロイする。`docs/`や資料ZIPをサイト配信対象に含めない。リポジトリ自体はPublicなので資料・Git履歴は閲覧可能。
- GitHub FreeのGitHub Pages利用条件・Actionsの権限は設定前に公式ヘルプで確認する。
- GitHub PagesのプロジェクトURLは通常`https://<user>.github.io/<repo>/`形式。Viteの`base`、アセット相対URL、SPAの直接アクセスを検証する。
- サイトの配信と、iPhone/iPadブラウザのIndexedDB保存を分離する。端末間のデータ移動はバックアップZIPを基本とする。

## 検証と承認
- 公開リポジトリ/公開Pagesであること、ログインUIの正誤入力と再読み込み、セッションリセット、パスワード変更後の挙動を確認する。
- ソースや公開JSに実秘密・トークン・個人制作素材がないことを監査する。ゲートをスキップしてもサイト本体が取得可能であることは既知の仕様。
- 画像出力・IndexedDB・バックアップ復元・タッチ編集をiPhone/iPad Safariで実測する。
- デプロイ、βURL案内、一般向け告知は、それぞれユーザーの承認後に行う。
