# 実装仕様契約B：座標系・レスポンシブレイアウト・自動構図補正

版：0.2／2026-11-05　性能や画質の実測値ではなく、検証可能にするための計算規則を定義。

## 1. 座標・単位
- キャンバスの左上を `(0,0)`。X右方向、Y下方向。表示用座標は論理キャンバスpxであり、端末のdevicePixelRatioとは別。
- 回転角度は**時計回りを正とする度**。画像のピボット（回転・拡大の中心）は既定で画像中心 `(0.5,0.5)`、利用者は変更可能。符号をAPIで統一。
- `width` に対する比率は基準領域の幅、`height`に対する比率は高さ。`x`は基準領域の左端（あるいは選んだアンカー）からのX方向、`y`は上端からのY方向。単位を属性ごとに保存。
- `fontSize`などの比率基準は属性に明記する（例：canvasWidth、safeHeight）。「%」だけの曖昧な値を保存しない。
- キャンバス外を表すため座標値の負数および比率1超を許す。スケールは正数。NaN/Infinityは拒否。
- 画像領域メタデータはEXIF向きを適用して正規化した**画像ローカル座標**。境界のポリゴン頂点は0..1、時計回り等の頂点方向を統一し、自己交差は拒否する。

## 2. 変換順序
配置インスタンスの画像ローカル点 `q`（ピボット中心を減算済）に対し、概念上の変換は `p = T(position) * R(rotation) * S(scale) * q`。描画APIの行列順と矛盾しないよう単体テストで固定。
- 親グループへ入れ子にする場合は `WorldMatrix = ParentWorldMatrix × LocalMatrix`。
- コンテナの形状・セーフエリアはワールド（キャンバス）座標に変換した後、交差や可視率を計算。
- 分割線は親画像コンテナローカル座標に定義し、同一親座標系で画像スロットをクリップ。

## 3. アンカーと制約
- アンカー9点：TL/TC/TR/CL/CC/CR/BL/BC/BR。アンカーからの`offsetX/Y`を持ち、何を基準とするか（canvas/safeArea/parent/otherNode）をIDとともに保存。
- 他Node基準は依存グラフを作り、トポロジカル順で解決。循環・参照切れを診断エラーとする。
- 位置・サイズの固定／最小最大／アスペクト維持は解決時に検証。条件衝突なら黙って配置を捏造せず警告と違反条件を表示する。
- セーフエリアは複数の可視多角形や重畳注意領域を許し、編集ガイドに限る。サービスの真の表示範囲と同一と断定しない。

## 4. 画像領域と構図目標の分離
- `ImageRegion`: 元画像に紐づくkeep/avoid多角形・priority・ラベル。画像ローカル座標。
- `CompositionReference`: ある配置インスタンスの元バナー位置、画像変形、元の可視クリップ領域、各Regionの表示率／基準点の相対座標／大きさ／退出方向。
- `CompositionSettings`: 角度固定/許可、許容値、倍率上限、評価重み、探索設定。
- 同じAssetでも各image-slotは独立した`CompositionReference`を持てる。
- keepの目標位置は元バナーの基準アンカーからの**相対距離**。右上隅基準なら、原点・符号を正規化し、キャンバス縦横比が変わっても比較できるようにする。

## 5. ハード制約（必ず満たす）
- rotationMode=fixed では `θ = θ0` を**値として厳密固定**する。
- rotationMode=bounded では `θ0-maxDelta <= θ <= θ0+maxDelta`。角度の正規化による境界跨ぎ（例：179°→−179°）を考慮し、最短角度差で評価する。
- `scale > 0`、設定されたscaleMin/scaleMaxを満たす。
- NaN・無限大・壊れたポリゴン・未検証の参照IDは不採用。
- ソフト条件が両立不能でもハード制約を破らない。結果候補がなければ理由を示す。

## 6. ソフト目標（近づける）
例示目的関数。**係数は暫定であり最適値が実証されたものではない**。
```
E(p) = W_keepVisible * KeepClippedRatio(p)
     + W_keepAnchor  * KeepAnchorPositionError(p)
     + W_keepSize    * KeepSizeError(p)
     + W_avoid       * AvoidVisibleRatio(p)
     + W_exit        * AvoidExitDirectionError(p)
     + W_scale       * abs(log(s/s0))
     + W_rotation    * abs(shortestAngleDifference(θ,θ0))/180
     + W_blank       * BlankAreaRatio(p)
```
- 可視／除外割合は、**変換後領域と実際のクリップ多角形の交差面積**で計算し、単純なBBoxだけで代替しない。
- KeepClippedRatioは1−可視面積/変換後keep面積。AvoidVisibleRatioは可視面積/変換後avoid面積。
- KeepAnchorPositionErrorは基準アンカーと目標点のずれをキャンバス幅/高さで正規化して比較。位置と大きさを混同しない。
- AvoidExitDirectionErrorは画像枠の指定した辺（左・下など）へ出ていくかどうかを、可視領域・領域代表点・外側方向で評価する。単なる非表示率だけではない。
- BlankAreaRatioは画像が覆っていないコンテナ面積比。**透明PNGの透明画素は背景が見える場合があるため、幾何学的な未被覆と画像alphaの差を診断する**。
- 複数Regionはpriorityによる重み付け。keep/avoid重複時は「矛盾あり」と表示し、通常の最適化を続けつつ残差を報告する。
- 失われた画像部分は復元できない。除外と保持の両立不能時は上位候補と不成立条件を見せる。

## 7. 探索・再現性
1. `sourcePlacement` と source/target profile寸法から初期候補を生成。
2. 回転固定ならθ候補は1つ、許可ならユーザー許容範囲内で粗い角度候補を生成。
3. 各角度で位置とlog-scaleを粗く探索。
4. 上位N件を局所的に細かく探索し、候補ごとの評価内訳を残す。
5. 同点時は**ハード制約違反0→元角度差が小さい→倍率差が小さい→位置変化が小さい→ID/数値辞書順**で一意に決定する。
6. 乱数を使う場合はseedを保存。アルゴリズム版・探索パラメータも保存して再現を可能にする。
7. UIには「変更前」「上位候補」「手動編集」を別の状態で表示。選択は同一Projectの操作としてUndoできる。

## 8. エラー・限界
- keepがクリップ内に完全に収まらない場合は、目標を強制するのではなく可視割合と原因を示す。
- 候補の比較中に実GPUでPNG生成することは必須ではない。まず幾何で評価し、上位候補だけ描画プレビューする。
- 極端に細いスプリットや画像サイズが小さいケースで数値的不安定があれば、精度上限・警告・手動操作へ切替。
- 自動調整は「提案」。見た目が気に入らなければユーザーが調整でき、元画像メタデータもTemplateも変えない。

## 9. 合格条件の例（自動テスト向け）
- Fixed：入力θ=−20°の場合、結果の`rotationDeg===−20`（小数浮動の計算経由ではない値を返す）。
- Bounded：θ0=−20°, maxDelta=15°なら全候補θ∈[−35°,−5°]。
- maxDelta=0°では、Fixedと同じ候補領域で探索し、スコア構成を揃える。
- 同じ入力、optimizerVersion、seed、探索設定なら候補順序・数値が再現する。
- keepとavoidの領域が完全一致し、両立不能のときに`conflict`診断が記録される。
- 分割領域が三角形のとき可視率を矩形BBoxとして誤計算しない。
- 設定した右上アンカーに対し、原配置と最適化候補の正規化誤差を数値で表示できる。
